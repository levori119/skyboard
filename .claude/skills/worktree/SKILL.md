# worktree נפרד לכל סוכן

> **הכלל:** כל סוכן עובד ב-worktree משלו, על branch משלו.
> **לא** שני סוכנים באותו עץ - גם לא "רק לרגע", גם לא "רק קובץ אחד".

זה כלל ולא המלצה. סוכן שמתחיל לעבוד על הריפו כשמישהו אחר כבר עליו - **מקים
worktree לפני שהוא קורא או כותב קוד**.

---

## שלב 0 - האם אני לבד כאן?

```bash
git worktree list          # מי עוד פרוס על הריפו
git status --short         # האם יש בעץ שינויים שאינם שלי
git branch --show-current  # על איזה ענף אני יושב
```

| מה רואים | מה עושים |
|---|---|
| worktree יחיד + עץ נקי + אני הסוכן היחיד | מותר לעבוד כאן |
| כל שאר המקרים (עוד worktrees, שינויים לא שלי, סוכן נוסף בסשן) | **להקים worktree - שלב 1** |

> קבצים בעץ שאינם שלך = **מישהו אחר עובד כאן**. לא לקמט אותם, לא "לנקות" -
> לדווח למשתמש ולהקים worktree משלך.

## שלב 1 - הקמה

```bash
git worktree add ../skyboard-<name> -b feature/<name>
cp .env ../skyboard-<name>/.env
```

`<name>` בקבב-קייס לפי הפיצ'ר או הסוכן (`zone-limits`, `gapi-integration`).

| | |
|---|---|
| **`node_modules`** | מקושר אוטומטית (symlink) דרך `.claude/settings.json` - אין `npm install` |
| **`.env`** | gitignored, **לא** עובר עם ה-worktree - חייב `cp` ידני |
| **ה-DB** | משותף לכל ה-worktrees (Neon אחד) |

מאותו רגע - **כל** פעולה (קריאה, כתיבה, `tsc`, `npm test`, `git add`, `commit`)
מתבצעת בתוך `../skyboard-<name>` בלבד.

### סוכני משנה (subagents)

סוכן משנה שכותב קוד מקבל worktree אוטומטי:

```
Agent(..., isolation: "worktree")
```

## שלב 2 - פורטים (רק אם מריצים `npm run dev` במקביל)

| worktree | API (`PORT` ב-`.env`) | Vite (`vite.config.ts`) |
|---|---|---|
| ראשי (`skyboard`) | 3001 | 5000 |
| סוכן נוסף | 3002 | 5001 |
| סוכן שלישי | 3003 | 5002 |

ה-proxy ב-`vite.config.ts` חייב להצביע ל-`PORT` של אותו worktree.
אם רק כותבים קוד + `tsc`/`test`/`build` - אין צורך, אין התנגשות פורטים.

> להרוג תהליך תקוע **רק לפי פורט**, לא לפי שם - `taskkill /F /PID <pid>`
> אחרי `netstat -ano | findstr :3002`. הריגה לפי שם מפילה את הסוכנים האחרים.

## שלב 3 - מיגרציות ב-DB משותף

ה-worktrees חולקים DB אחד. מיגרציה שסוכן אחד מריץ **משפיעה על כולם**:

- `ADD COLUMN IF NOT EXISTS` בלבד
- **אף פעם** לא `DROP` / `ALTER ... TYPE` על עמודה שסוכן אחר קורא
- שני סוכנים שנוגעים באותה טבלה - לתאם דרך המשתמש לפני ההרצה

---

## שלב 4 - לפני קימוט

```bash
git status --short                     # רק הקבצים שלי?
grep -n "<שורה שערכתי>" <קובץ>          # השינוי באמת על הדיסק?
```

הקימוט הוא על ה-branch של ה-worktree - `feature/<name>` - ולא על main.

---

## שלב 5 - סגירה אחרי מיזוג

```bash
git worktree remove ../skyboard-<name>
git branch -d feature/<name>
git worktree prune          # מנקה רישומים של תיקיות שנמחקו ידנית
```

## למה - זה קרה בפועל

כששני סוכנים עבדו על אותו working tree באותו ענף:

| מה קרה | התוצאה |
|---|---|
| סוכן א' ערך `managers.tsx`, סוכן ב' כתב את אותו קובץ | השינויים של א' **נמחקו בשקט**. התגלה רק בקומיט, במקרה |
| סוכן א' ערך את `CLAUDE.md`, וסשן אחר שחזר את הקובץ | הקומיט יצא **ריק מהשינוי** - התוכן נעלם בין העריכה ל-`git add` |
| סוכן א' קימט "הכל" | הקומיט נשא איתו קוד של סוכן ב' באמצע עבודה - קבצים שזורים, אי-אפשר להפריד ברמת קובץ |
| סוכן ב' הוסיף JOIN שגוי ל-route של סוכן א' | `GET` נפל ב-500, הפיצ'ר "לא עבד", ואיש לא ידע של**מי** השבר |
| סוכן ב' הוסיף שדה לטופס בלי להשלים אותו | `tsc` נשבר בעץ המשותף, וכל סוכן אחר "ירש" בנייה אדומה |

הנזק אינו רק התנגשות: הוא **אובדן שקט**. `git` אינו מתריע כששני תהליכים כותבים
לאותו קובץ בזה אחר זה - הכתיבה האחרונה מנצחת, בלי אזהרה ובלי conflict.

## מלכודות

| מלכודת | מה קורה | פתרון |
|---|---|---|
| שכחת `cp .env` | השרת עולה בלי `DATABASE_URL` ונופל | `cp .env ../skyboard-<name>/.env` |
| שני worktrees על **אותו** branch | git מסרב (`branch is already checked out`) | branch משלך לכל worktree |
| מחקת את התיקייה ידנית | `git worktree list` מציג רישום מת | `git worktree prune` |
| ערכת קובץ בעץ הראשי "רק לרגע" | דרסת סוכן אחר | לחזור ל-worktree שלך ולערוך שם |
| שני סוכנים על אותו פורט | `EADDRINUSE` או בקשות שהולכות לשרת הלא נכון | טבלת הפורטים בשלב 2 |
