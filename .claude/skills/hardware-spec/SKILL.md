# תפקיד: מהנדס תשתיות - SKY-KING

אתה מגדיר את דרישות החומרה והביצועים של SKY-KING מול **חיל האוויר**.
התוצר הוא **מסמך HTML להגשה** (`HARDWARE_SPEC.html`) שעובר ועדת רכש ומטמיע תשתיות.

> **הרף:** לא "מה נחמד שיהיה" אלא "מה עובר ועדת רכש, ומה יסופק בפועל אם לא נכתוב את זה במפורש".
> מפרט חסר = ציוד שמגיע ולא מאפשר הפעלה. מפרט מנופח = הבקשה נפסלת כולה.

---

## עקרונות יסוד (הנחיות אורי - לא לסטות)

1. **כל מספר נמדד, לא מוערך.** לכל שורה בטבלת הנתונים יש **עמודת מקור**. אם משהו לא נמדד -
   הוא הולך לסעיף "הנחת תכנון", לא לטבלת המדידות.
2. **הפרדה מפורשת בין נמדד לבין הנחה.** סעיף ייעודי בסוף המסמך אומר מה נמדד, מה מונח,
   ואיך מאמתים את ההנחה לפני הרכש הגדול.
3. **סיווג לכל שורה:** `חובה` / `מומלץ` / `לבחירת הארגון`. בלי סיווג, כל שורה נראית כמו
   משאלה ואפשר לקצץ בה.
4. **מינימום ומומלץ - תמיד שניהם.** מספר יחיד מזמין ויכוח, טווח מזמין החלטה.
5. **סעיף "מה איננו נדרש" הוא חובה.** הוא מה שהופך את הבקשה לאמינה. מפרט שמבקש הכל
   נקרא כמנופח; מפרט שמוותר מרצון על GPU בשרת ועל SAN נקרא כמדוד.
6. **שרתים ב-vCPU, לא בדגמי מעבד.** כדי שאפשר יהיה לספק מכונות וירטואליות מהחווה הקיימת.
   **עמדות בדגם מעבד מפורש** - שם הביצועים הם דרישה מוחלטת ולא יחידת חשבון.
7. **כל נימוק נגמר בהשלכה תפעולית**, לא בהסבר טכני. לא "Node חד-תהליכי" אלא
   "בכניסת משמרת עשרות עמדות עולות בו-זמנית וכל אחת מושכת מפה של 1.3MB".

## שלב 1 - מדידות חובה (לפני שכותבים מספר אחד)

הרץ את כל הבלוק. **בלי המדידות האלה אין מסמך.**

```bash
# ── עומס פר עמדה: היסטוגרמת מחזורי ה-polling בלקוח ──
grep -rhoE "setInterval\([^,]{1,60}, *[0-9]{4,6}\)" src/ --include=*.tsx --include=*.ts \
  | grep -oE "[0-9]{4,6}\)$" | tr -d ')' | sort -n | uniq -c
# סכום 1/interval על כל מה שמעל 1000ms (1000 = שעונים מקומיים, לא רשת) = בקשות לשנייה

# ── היקף ה-API ──
grep -rhoE "(router|app)\.(get|post|put|patch|delete)\(" server/ server.js | wc -l
ls server/routes | wc -l

# ── עמדות מוגדרות + גודל ה-DB + פילוח + השהיה ──
# heredoc ולא -e: מונע גיהוץ מרכאות בין bash ל-JS ל-SQL
node --env-file-if-exists=.env --input-type=module << 'NODEJS'
import pg from 'pg';
const p = new pg.Pool({ connectionString: process.env.DATABASE_URL, max: 2 });
const q = async s => { try { return (await p.query(s)).rows } catch (e) { return [{ err: e.message }] } };
console.log('DB:', JSON.stringify(await q('SELECT pg_size_pretty(pg_database_size(current_database())) size')));
console.log('presets:', JSON.stringify(await q('SELECT count(*) FROM workstation_presets')));
console.log('tables:', JSON.stringify(await q("SELECT count(*) FROM information_schema.tables WHERE table_schema NOT IN ('pg_catalog','information_schema')")));
console.log(JSON.stringify(await q("SELECT c.relname tbl, pg_size_pretty(pg_total_relation_size(c.oid)) sz FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace WHERE n.nspname='public' AND c.relkind='r' ORDER BY pg_total_relation_size(c.oid) DESC LIMIT 10")));
const l = []; for (let i = 0; i < 5; i++) { const t = Date.now(); await q('SELECT 1'); l.push(Date.now() - t); }
console.log('RTT ms:', l.join(','));
await p.end();
NODEJS
```

**מדידות שאינן בפקודה ויש לשלוף מהתיעוד:**

| נתון | מקור בפרויקט |
|---|---|
| זמן עליית שרת + מספר ה-round-trips ב-`initDb` | [DEPLOY.md](../../../DEPLOY.md) |
| זמן תמלול מקומי + גודל המודל | [electron/whisper.cjs](../../../electron/whisper.cjs) - הערות המדידה בראש הקובץ |
| הכפלת עומס בתצוגת עמדות שכנות | [REFACTOR_LOG.md](../../../REFACTOR_LOG.md) - `installPeekPollThrottle` |
| עומס נמדד בפועל פר עמדה | פרויקט **LOADRUNNER** (ריפו נפרד) |

## שלב 2 - היקפי הפריסה (עובדות נעולות - עודכן 08.2026)

**אלה נתוני אמת מהצוות. לא להמציא, לא לשנות בלי שנאמר במפורש.**

| אתר | סוג | VMP | בט"ש | לחימה |
|---|---|---|---|---|
| יב"א 509 | יחידת בקרה | 2 | 30 | 60 |
| יב"א 506 | יחידת בקרה | - | 30 | 60 |
| יב"א 528 | יחידת בקרה (חצי) | - | 15 | 30 |
| מגדל חא 8 | מגדל פיקוח | 1 | 6 | 6 |
| 6 מגדלים נוספים | מגדל פיקוח | - | 36 | 36 |
| **סה"כ** | **10 אתרים** | **3** | **117** | **192** |

- **2.5 יחידות בקרה** (509, 506, 528). 30 עמדות ליחידה בבט"ש, **60 בלחימה**.
- **7 מגדלים**, 6 עמדות בכל אחד. **המגדלים אינם משנים היקף בלחימה.**
- **VMP** = 2 עמדות ביב"א 509 + עמדה אחת במגדל חא 8.

**הנחות שסומנו במסמך כטעונות אישור:**
- 528 היא "חצי היחידה" (15/30). הסכום הכולל אינו משתנה, מפרט האתר הבודד כן.
- מספר התחנות הפיזיות לרכישה = מספר הלחימה (192), גם אם בבט"ש מאוישות 117.

## שלב 4 - הדרישות הקריטיות (חוזרות בכל גרסה של המסמך)

אלה מה שיסופק **שגוי** אם לא ייכתב במפורש. תמיד בתיבה אדומה בתקציר:

1. **שרת ה-DB באותו rack/VLAN עם האפליקציה, RTT < 1ms.**
   `initDb` מבצע ~300 פניות סדרתיות: ב-70ms זה 36 שניות עלייה, ב-0.5ms זה שתי שניות.
   כל בקשת עמדה מבצעת 2-3 שאילתות, ולכן כל מילישנייה מוכפלת.
2. **העמדה היא תחנת עבודה פיזית - לא thin client ולא VDI.**
   התמלול רץ במעבד העמדה (האודיו לא עוזב אותה, וזו התשובה לסקר האבטחה),
   וזמן התגובה של העט לא שורד שולחן עבודה מרוחק.
3. **שרתים נרכשים בגודל לחימה כבר בשלב הבט"ש.** הפער בעלות שולי; החלפת שרתים
   באתר מבצעי ברגע המעבר ללחימה אינה אפשרית. **תחנות** כן מתפצלות לשלבים.
4. **Windows Ink מופעל** - בלעדיו העט לא עובד בגרירות (תקלה שאומתה בשטח).
5. **x64 בלבד** - בינארי התמלול והמתקין נבנים ל-Windows x64.
6. **שרת בכל אתר, לא מרכז אחד** - שרידות מול נפילת קו, השהיה < 10ms, ועומס מבוזר.
   אם בכל זאת נבחר מרכז - דרישת ההשהיה מכל בסיס הופכת לתנאי סף.
7. **NTP משותף, שרתים ב-UTC** - המערכת מציגה את שעת המידע ואת גילו. הסטת שעון =
   מידע שדה שגוי. (ראה גם האיסור על `TIMESTAMP` בלי tz ב-CLAUDE.md.)
8. **תעודת TLS מ-CA פנימית + הפצת שורש** - הלקוח השולחני לא ייטען מול תעודה לא מהימנה.
