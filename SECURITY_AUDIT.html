1. תקציר מנהלים

שורה תחתונה

המערכת במצבה הנוכחי אינה עומדת בסף הכניסה של רשת מסווגת, ולא של רשת ארגונית מוגנת. אין בקוד שכבת אימות זהות (authentication) ואין אכיפת הרשאות (authorization) - אף אחד מ-397 ה-endpoints אינו מוגן. מסך הכניסה קיים אך הוא קוסמטי בלבד: הוא רץ בדפדפן, וכל מי שיש לו קישוריות רשת לשרת יכול לעקוף אותו לחלוטין בפקודת curl אחת, לקרוא את כל בסיס הנתונים התפעולי, לשנות אותו, ולמחוק את יומן הביקורת.

בנוסף, גיבוי מלא של בסיס הנתונים (20.6MB, כולל טבלת אנשי הצוות ויומן הפעילות) מגובה בתוך מאגר ה-git, והמערכת כולה מתארחת כיום על ספקי ענן ציבוריים זרים (Neon/ארה"ב, Railway/ארה"ב, GitHub/ארה"ב).

זו איננה גזירת גורל. הליקויים אופייניים למערכת שנבנתה כ-MVP תפעולי מהיר, לא כמוצר מאובטח. הבשורה הטובה: הליבה נקייה מהבעיות הקשות-לתיקון. אין SQL Injection בשום מקום (כל השאילתות פרמטריות), ארכיטקטורת הנתונים מסודרת, ובידוד סביבות התרגול נבנה בקפידה. הפער הוא בשכבות שנוספות מעל הקוד הקיים, ולא בכתיבה מחדש שלו. אומדן: 6-10 שבועות עבודה להבאה לסף שאפשר להציג לקב"ט/מלמ"ב.

5. ממצאים קריטיים - פירוט

SK-01קריטיאין אימות זהות בשום endpoint
מה נמצא: server/app.js מרכיב 21 routers עם 397 endpoints. בין ה-middleware יש רק cors(), express.json() ו-middleware הסביבות. אין ולו middleware אחד שבודק מי המשתמש. חיפוש אחר jwt, session, req.user, Authorization בכל תיקיית server/ מחזיר אפס תוצאות רלוונטיות.
מה זה אומר בפועל: תוקף עם קישוריות רשת לשרת (עמדה שכנה, מחשב שהוכנס לרשת, מכשיר Wi-Fi) יכול:
curl http://SERVER:3001/api/crew-members     # כל אנשי הצוות + מספרים אישיים + דגלי admin
curl http://SERVER:3001/api/strips           # כל הסטריפים התפעוליים
curl http://SERVER:3001/api/sectors          # מבנה הסקטורים
curl -X DELETE http://SERVER:3001/api/activity-log      # מחיקת כל יומן הביקורת
curl -X POST http://SERVER:3001/api/crew-members \
     -H 'Content-Type: application/json' \
     -d '{"first_name":"X","last_name":"Y","personal_id":"1","is_admin":true}'   # יצירת admin
למה זה קריטי במיוחד כאן: זו מערכת שמציגה מידע שדה מבצעי בזמן אמת. קריאה = איסוף מודיעין. כתיבה = הזנת מידע כוזב למסך של בקר טיסה. מחיקה = שיבוש תפעולי.
התיקון:
  1. להוסיף middleware אימות גלובלי לפני כל ה-routers ב-server/app.js, בגישת deny-by-default. רשימת היתר מפורשת רק ל-/api/health ולנתיב ההתחברות.
  2. לספק טוקן חתום (JWT קצר-מועד עם refresh, או session cookie מסוג HttpOnly; Secure; SameSite=Strict) בזמן ההתחברות. אני ממליץ על cookie ולא JWT ב-localStorage - הוא חסין ל-XSS ומתאים למערכת עם origin יחיד.
  3. להוסיף שכבת הרשאות (RBAC): requireRole('admin') על כל ה-endpoints הניהוליים. מתוך 397 יש 73 DELETE ו-113 POST - כולם דורשים סיווג.

SK-02קריטיההרשאות נאכפות בצד לקוח בלבד
מה נמצא: זרימת ההתחברות (src/App.tsx:147-215) היא: הלקוח מושך את רשימת אנשי הצוות מ-GET /api/crew-members, המשתמש בוחר את עצמו מרשימה, והלקוח שומר את האובייקט (כולל is_admin) ב-sessionStorage. כל בדיקות ההרשאה בקוד הן מהצורה {selectedCrewMember.is_admin && ...} ב-JSX.

התיקון: ההרשאה חייבת להיקבע בשרת מהטוקן החתום, לא מגוף הבקשה ולא מ-state של הלקוח. הבדיקות ב-JSX נשארות (חוויית משתמש), אבל הן מפסיקות להיות מנגנון האבטחה.

  1. אין SQL Injection בשום מקום. נסרקו כל 397 ה-endpoints. כל שאילתה משתמשת ב-placeholders ($1, $2). גם השאילתות הדינמיות (strips.js:535, admin.js:539) בונות רק את שמות העמודות מליטרלים קשיחים בקוד, ואת כל הערכים מעבירות כפרמטרים. זו משמעת מרשימה על פני קוד בהיקף הזה, וזו הפגיעות שהכי קשה לתקן בדיעבד.
  2. בניית שם הסכמה מוגנת מפורשות. env-context.js:22 - שם הסכמה נגזר אך ורק ממספר שאומת כשלם בטווח, עם הערה מפורשת בקוד שמסבירה למה. בדיוק המקום שבו רוב הפרויקטים נכשלים.
  3. בידוד סביבות התרגול נבנה בקפידה יוצאת דופן. ההבנה ש-SET LOCAL חייב לרוץ בתוך טרנזקציה מול pgbouncer, והשמדת ה-connection בשחרור כדי למנוע דליפת search_path ל-pool המשותף (pool.js:40-73) - זה זוהה אמפירית ותועד. עבודה ברמה גבוהה.
  4. Docker מוקשח סביר. בנייה רב-שלבית, npm ci דטרמיניסטי מה-lock, ו-USER node (לא root). ה-.dockerignore מחריג את .env.
  5. Electron מוגדר נכון בעיקר. contextIsolation:true ו-nodeIntegration:false - שתי ההגדרות הכי חשובות, נכונות.
  6. ניהול סודות בסיסי תקין. .env ב-.gitignore, ולא נמצאו מחרוזות חיבור בהיסטוריית git (נבדק עם git log -S). החיבור ל-DB מוגדר עם sslmode=require ו-channel_binding=require - הצפנת תעבורה מלאה ל-DB.
  7. המשמעת ההנדסית בפרויקט גבוהה. כלל ה-TIMESTAMPTZ (עם תיעוד הבאג שהוליד אותו), התבנית הנכונה לרינדור ללא innerHTML ב-configEditors.tsx, הזיהוי המקומי ללא רשת ב-HandwritingPad.tsx, וההערות בעברית שמסבירות למה ולא רק מה. הדפוסים הנכונים כבר קיימים בקוד - הם פשוט לא הוחלו בעקביות. זו נקודת פתיחה טובה מאוד לתיקון.

10. ספריות צד ג' ומדינות מקור

איך לקרוא את הטבלאות: "מדינת מקור" מציינת את מיקום החברה או הארגון המתחזק. בפרויקטי קוד פתוח קהילתיים, שבהם אין ישות משפטית אחת, צוין מיקומו של המתחזק הראשי - זה מידע רלוונטי לסקר ביטחוני אבל הוא לא אומר שהקוד "שייך" למדינה ההיא. תרומות מגיעות מכל העולם, וזו בדיוק הנקודה שסקר שרשרת אספקה בא לטפל בה.

הסתייגות: חלק מהשיוכים מבוססים על ידע כללי ולא על אימות מסמכי. לפני הגשה רשמית חובה להפיק SBOM (פרק 12) ולאמת מול package.json ו-repository של כל חבילה. הטבלה מכסה את 25 התלויות הישירות ואת התלויות העקיפות הבולטות; סך הכל בעץ ה-production יש 180 חבילות, ו-746 כולל פיתוח.

  1. בינאריים נייטיביים מוכנים מראש (@napi-rs/canvas, @swc/core, esbuild): קוד מכונה שיורד מהאינטרנט ורץ אצלכם, שלא בניתם מהמקור. זה הפריט המדאיג ביותר בפרק, ללא קשר למדינה.

  3. שירות ענן זר בלב פיצ'ר (SK-17 - MyScript): לא רק תלות קוד, אלא זרימת מידע החוצה.

ההמלצה המרכזית: להקים registry פנימי (Verdaccio / Nexus / Artifactory), להקפיא את כל התלויות בגרסאות מאומתות עם hash, ולהריץ npm ci --ignore-scripts מולו. זה עונה על שלוש הנקודות בבת אחת וזה מה שמצופה מספק לגוף ביטחוני.
